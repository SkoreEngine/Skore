# Header Cleansing Audit (APX-272)

**Scope:** all first-party headers (`core/` engine + `plugins/`). `editor/`,
`app/`, `player/`, `tests/` headers are inventoried where relevant but are not
part of the plugin cleansing follow-ups.
**Nature:** read-only investigation. No source changed. This file is the written
deliverable; all greps below are re-runnable verbatim from the repo root.

---

## 0. Method (re-runnable commands)

```bash
# All first-party headers (engine + plugins + hosts + tests):
find core plugins editor app player tests -name '*.h' | sort

# Static function declarations/definitions (plain `static`, incl. macros):
grep -rn -E '^\s*static' --include='*.h' core/ plugins/ editor/ app/ player/ tests/ | grep -v testdata

# Static inline function definitions with bodies:
grep -rn -E 'static\s+(inline\s+)?[a-zA-Z_][a-zA-Z0-9_]*\s+[a-zA-Z_][a-zA-Z0-9_]*\s*\(' --include='*.h' core/ plugins/ editor/ app/ player/ tests/ | grep -v testdata

# SK_FINLINE (macro -> `static inline` / `static __forceinline`) bodies:
grep -rn 'SK_FINLINE' --include='*.h' core/ plugins/

# Include map for a header (who uses it):
grep -rln '<name>.h' --include='*.c' --include='*.h' --include='*.cpp' core/ app/ player/ editor/ plugins/ tests/

# Install/export rules that touch headers:
grep -rn 'install(' --include='*.cmake' --include='CMakeLists.txt' . | grep -v thirdparty
grep -rn 'GLOB\|target_include_directories\|add_library(.*INTERFACE' --include='CMakeLists.txt' core/ app/ player/ editor/ plugins/ tests/ cmake/
```

## 1. Headers declaring or defining a `static` function

### 1.5 Notable negatives

- **`plugins/vulkan_render_device/vulkan_utils.h` contains no `static` function

  (`grep -oE '^[a-zA-Z_]+ [a-zA-Z_0-9]+\(' vulkan_utils.h` cross-referenced per

  cross-TU visibility via an internal header.
- No header in the tree carries a **body-less `static` forward declaration**
  (dead/incomplete `static` prototype). The only `static` declarations in
  headers are the `SK_TEST`/`SK_UI_TEST` macro expansions (1.1).
- Audit finding: the task example `_init`-style statics do not exist in this
  repo — the static-in-header surface is entirely inline accessors and
  macro-generated test bodies. The cleansing work is therefore dominated by
  **internal-header naming/isolation** (§2, §5), not by moving statics.

## 3. Current header install / export / glob mechanism

**There is no `install()` rule anywhere in first-party CMake** (verified:
`grep -rn 'install(' --include='*.cmake' --include='CMakeLists.txt' . | grep -v thirdparty`
→ empty; the only `install` strings are `CMAKE_INSTALL_RPATH`). Headers are
distributed exclusively through **include directories + INTERFACE targets**,
and every plugin dir is globbed wholesale:

| Rule (file) | What it does to headers |
|---|---|
| `CMakeLists.txt` — `sk_embed_type_ids_in_dir(core app player editor plugins tests)` | **Rewrites headers in place** at configure time: replaces `SK_TYPE_ID("name")` with the MD5-hashed 3-arg form in every `*.h/*.c/*.hpp/*.cpp` under those dirs (`cmake/cmake_functions.cmake: sk_embed_type_ids_in_file`) |
| `CMakeLists.txt` — `sk_check_header_isolation(core app player editor plugins tests)` | Configure-time scan of every `*.h`; `FATAL_ERROR` if a header includes `<pthread.h>`, `<windows.h>`, `<semaphore.h>`, `<sched.h>`, `<mtx.h>`, `<thread.h>`, `<threads.h>` |
| `cmake/cmake_functions.cmake` — `sk_add_plugin(<name> SOURCES <globbed *.h *.c>)` | Per plugin: `file(GLOB_RECURSE *.h *.c)` → SHARED target; creates `sk-<name>-lib` INTERFACE with `target_include_directories(... INTERFACE ${CMAKE_CURRENT_SOURCE_DIR})` — **the whole plugin dir (including `*_internal.h`, `vulkan_utils.h`, `testdata/*.h`) lands on every consumer's include path**; `sk_target_enable_tests` adds `SK_TESTS` |
| `core/CMakeLists.txt` | `file(GLOB_RECURSE SKORE_CORE_SOURCES CONFIGURE_DEPENDS *.h *.c)`; `sk-core` PUBLIC include dir = whole `core/`; `sk-core-lib` INTERFACE (headers only); `sk-test`/`sk-core-tests` same glob |
| `app/CMakeLists.txt`, `editor/CMakeLists.txt` | `GLOB_RECURSE *.h *.c`; `target_include_directories(... PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})` (editor also adds 4 plugin dirs); `sk-app-tests`/`sk-editor-tests` add plugin dirs privately (platform_window, entities, dxc_compiler, render_graph, render_device, profiler) |
| `player/CMakeLists.txt` | `GLOB_RECURSE *.h *.c` into `sk-player`; PRIVATE include dirs for `plugins/platform_window`, `plugins/ui`, `plugins/ui/testdata`, `plugins/render_graph`, `plugins/render_device`, `plugins/dxc_compiler`, `plugins/profiler` |
| `plugins/*/CMakeLists.txt` | Each `file(GLOB_RECURSE *.h *.c)` + `sk_add_plugin`; extra deps (e.g. ui links `sk-render-device-lib`, `sk-dxc-compiler-lib`; vulkan links `sk-render-device-lib`, `sk-platform-window-lib`) |
| `tests/CMakeLists.txt`, `tests/integration/CMakeLists.txt` | Link `sk-*-lib` INTERFACE targets; extra `target_include_directories` for `plugins/ui/testdata` and plugin dirs |
| `scripts/check-windows-abi.sh` | clang-tidy `-I` for every `plugins/*` dir + every `plugins/*/testdata` dir (so header renames stay found); `plugins/ui/testdata` mirrored for the font header |
| `cmake/cmake_functions.cmake` — `sk_copy_dxc_shared_library` | Copies DXC **binaries** (`.dll/.so/.dylib`), not headers |

**Consequence:** "internal" is convention only (name + non-use). Nothing in the
build system curates a public header set; any file dropped in a plugin dir is
globbed into the plugin target and re-exported through `sk-<name>-lib`. This is
the root cause the cleansing addresses.

## 4. Convention decision

### 4.1 Internal-header naming: use the `.internal.h` suffix (recommended)

**Recommendation:** plugin-internal headers are named `<name>.internal.h`
(e.g. `vulkan_utils.h` → `vulkan_utils.internal.h`), replacing the current
inconsistent `_internal.h` style.

Rationale:
- **Unambiguous extension split.** `.internal.h` is a clear filename stem
  (`vulkan_utils` + internal marker), whereas `vulkan_render_device_internal.h`
  reads as if "device_internal" were the module and is easy to confuse with the
  public `vulkan_render_device.h` (same prefix, one word apart).
- **Grep- and glob-friendly.** `file(GLOB_RECURSE *.h …)` still picks it up;
  clang-format (matches by suffix), cppcheck, and `check-windows-abi.sh`
  (whole-dir `-I`) are unaffected. `grep -rn '\.internal\.h'` gives a clean,
  complete inventory of internal headers.
- **Strong no-API signal.** The dot suffix visually separates from public
  `<plugin>.h`; downstream tooling/IDEs and future packagers can exclude
  `*.internal.h` from exported header sets with a single pattern, and can
  refuse to ship them.
- **Test macros keep working.** `SK_UI_TEST`/`SK_TEST` bodies live in `.c`;
  renaming headers does not touch macro-generated statics.

Alternatives considered:

| Option | Verdict |
|---|---|
| `_internal.h` suffix (status quo: `ui_internal.h`, `vulkan_render_device_internal.h`) | Viable but inconsistent today (missing on `vulkan_utils.h`, `profiler_core.h`); ambiguous stems for already-long plugin names; keep only if the team prefers zero churn — rejected because the point of the audit is to make the convention explicit and uniform |
| `_private.h` | "private" is overloaded (C++ access control, file-static); "internal" matches existing intent wording ("Private UI plugin state", "Private types for the Vulkan render device plugin") |
| `internal/` subdirectory per plugin | Strongest isolation, but breaks the flat per-module layout AGENTS.md prescribes, requires include-path surgery (`#include "internal/foo.h"`), and fights the glob/INTERFACE model — overkill for 4 headers |
| `__` / leading-underscore prefix | Reserved-ish identifiers in C (`_` + uppercase, `__`) — rejected on standards grounds |
| No marker (rely on doc comments) | Current state — failed: `vulkan_utils.h` and `profiler_core.h` had no marker at all; nothing enforced it |

### 4.2 Where `static` helpers belong

Rule: **a file-local helper is declared and defined `static` in the `.c`
translation unit that owns it (e.g. `plugin_entry_point.c`) — never in a
header.** Cross-TU helpers that several `.c` files of one plugin share go in the
plugin's `*.internal.h` with normal (non-`static`) linkage, or as
`SK_FINLINE` static-inline in the internal header when they are hot-path
converters.

- Public headers may keep `SK_FINLINE` accessors (1.2) — that is the
  sanctioned inline surface, not a violation.
- Test-registration macros (`SK_TEST`, `SK_UI_TEST`) keep expanding `static`
  functions at their invocation sites in `.c` files.
- Enforcement (follow-up, optional): add a configure-time guard in the style of
  `sk_check_header_isolation` that (a) fails if a `*.h` (public or internal)
  contains a non-inline `static` function *declaration*, and (b) fails if a
  `*.internal.h` is included from outside its own plugin directory. Both are
  one-grep checks.

## Summary

1. **Static-in-header:** zero violations of the "no plain `static` in headers"
   rule; all static-in-header content is (a) `SK_FINLINE` inline accessors
   (sanctioned, 1.2), (b) macro-generated test bodies (sanctioned, 1.1), or
   (c) deliberate non-`always_inline` macro backing in `profiler.h` (1.3).
   `vulkan_utils.h` itself declares **no** static functions — its 43 helpers are
   all cross-TU and need the internal header.
2. **Internal-only headers:** 5 plugin-internal (vulkan_utils.h,
   vulkan_render_device_internal.h, ui_internal.h, profiler/core/profiler_core.h,
   testdata font) + 7 host/tests-internal.
3. **Export mechanism:** no install rules; wholesale per-dir glob +
   INTERFACE-target include paths mean "internal" is convention, not
   enforcement.
4. **Convention:** `<name>.internal.h` for plugin-internal headers; `static`
   helpers live in the owning `.c`.
5. **Follow-ups:** 3 renames with 21 in-plugin include-site edits total; 10
   public headers flagged for escalation, never renamed.
