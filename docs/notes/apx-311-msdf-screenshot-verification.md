# APX-311: MSDF screenshot verification after APX-270

Independent vision pass over the APX-268 `sk-text-screenshot` matrix after
the APX-270 bake/shader range fix. **No rendering code was changed.**

## Run

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DSK_ENABLE_CLANG_TIDY=OFF
cmake --build build --target sk-text-screenshot
export VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json
(cd build/bin && ./sk-text-screenshot --verify \
    --out-dir ../../docs/notes/apx-311-text-screenshot)
```

- Harness: `sk-text-screenshot` (APX-268 / APX-271), viewport 640×480, DejaVuSans.ttf Regular
- Pipeline: MSDF only. The FreeType R8 path was retired in APX-271, so
  `--mode both` no longer exists. Expected reference is the APX-269
  FreeType capture set; the APX-269 MSDF set is the pre-fix regression baseline.
- `--verify`: every sample byte-identical on a second capture (raw RGBA + PNG)
- Vulkan: lavapipe. Paint uses the **CPU MSDF coverage path** (median +
  `screen_px_range` + smoothstep). `SK_UI_MSDF_GPU` unset (GPU atlas
  sampling is still tofu on lavapipe)
- New captures: `docs/notes/apx-311-text-screenshot/text-screenshot/msdf/`
- Side-by-side / diffs / zooms: `docs/notes/apx-311-text-screenshot/compare/`
- Compare plates were generated by `docs/notes/apx-311-make-compare.py`
- Sample matrix (same as APX-269): `pangram` (20 px), `sizes` (8 / 12 / 20 / 48 / 96 px),
  `colors_alpha`, `scaled` (14 px logical / 28 px physical and 6 px logical),
  `glyph_grid` (printable ASCII 0x20–0x7E at 16 px), `atlas_msdf`
- Weights: the harness has a single Regular face. There is no bold/italic
  sample in this matrix.

Determinism: **pass** (`pangram` 28897, `sizes` 49242, `colors_alpha` 35136,
`scaled` 32471, `glyph_grid` 29368, `atlas_msdf` 57393 bytes). PNG sizes
dropped vs the pre-fix MSDF set (less fringe = more compressible; atlas
unused texels are now near-black instead of mid-gray).

## Checklist (same grades as APX-269)

| Criterion | How it was judged |
| --- | --- |
| Crisp edges at large sizes | 48 px / 96 px on `sizes`; 96 px “T” / “brown” zooms |

Overall: **the APX-269 blocking regressions are gone.** Letterforms,
corners, color identity, alpha, and atlas packing remain in the right
family, and the wide anti-aliased band (halo / dim interiors / olive
fringe) from the bake ↔ unorm ↔ shader range mismatch is gone. MSDF is
now in the same visual family as the APX-269 FreeType reference at
12–96 px.

**APX-270 is not exhausted.** Remaining deltas versus hinted FreeType
are the same residual notes APX-269 already accepted (1 px AA vs
stair-step, unhinted advances, 8 px coverage-floor contrast). They are
**not** a new distinct cause and do **not** require replanning atlas
resolution, per-size atlases, or the antialiasing formulation to close
the APX-269 defects.

## D1 — large-size halo / glow — **RESOLVED**

- **Class:** distance range / shader median+smoothstep
- **Samples:** `sizes.png` 48 px and 96 px; also `scaled.png` 28 px physical
- **Images:**
  - [msdf/sizes.png](apx-311-text-screenshot/text-screenshot/msdf/sizes.png)
  - [compare/sizes_side_by_side.png](apx-311-text-screenshot/compare/sizes_side_by_side.png)
  - [compare/sizes_96_T_trio.png](apx-311-text-screenshot/compare/sizes_96_T_trio.png)
  - [compare/sizes_96_brown_trio.png](apx-311-text-screenshot/compare/sizes_96_brown_trio.png)
  - [compare/sizes_48_The_trio.png](apx-311-text-screenshot/compare/sizes_48_The_trio.png)
- **Was:** every large glyph wrapped in a 3–4 px soft gray outline; 96 px
  “T” / “brown” looked backlit. Pre-fix 96 px “T” crop: 3111 ink / mean L
  179.7; “brown” 10545 / 177.7.
- **Now:** interiors are solid (peak L 242.9, same family as FreeType).
  96 px “T” crop: 2378 ink / mean L 224.6 vs FreeType 2583 / 218.3.
  96 px “brown”: 7919 / 222.9 vs FreeType 8731 / 217.9. Extra halo pixels
  are gone; mean L rose because stems are no longer washed out.
- **Corners:** 96 px “T”, “k”, “x”, “b”, “w” stay right-angled / pointed.
  Not the classic single-channel SDF rounding failure.
- **Not this defect:** 48 px “The quick” overlapping the 96 px line —
  harness row height `size + 20` is still too short. Present on the
  FreeType reference as well.

## D3 — yellow-on-blue olive fringe — **RESOLVED**

- **Class:** shader AA (wide coverage × blend), not a bad median
- **Sample:** `colors_alpha.png` “Opaque yellow”
- **Images:**
  - [msdf/colors_alpha.png](apx-311-text-screenshot/text-screenshot/msdf/colors_alpha.png)

  - [compare/colors_white_trio.png](apx-311-text-screenshot/compare/colors_white_trio.png)
- **Was:** yellow crop mean RGB `(130, 136, 77)` vs FreeType `(178, 182, 47)`.
- **Now:** `(170.0, 174.4, 52.0)` vs FreeType `(178.3, 182.4, 46.8)`.
  Peak interior texels are `(255, 255, 0)` — yellow, not olive. Opaque

  AA (coverage × yellow over blue). It is not the 3–4 px olive band.
- 96 px white “T” max |R−G| / |R−B| is 5 / 16 (now) vs 2 / 11 (FreeType).
  Median is combining channels; no RGB split.

## Small-size coverage clamping — **pass** (notes)

- **Class:** `screen_px_range` 1.0 floor (deliberate; not D1)
- **Samples:** `sizes` 8 px / 12 px; `scaled` 6 px logical (12 px physical)
- **Images:**
  - [compare/sizes_8px_trio.png](apx-311-text-screenshot/compare/sizes_8px_trio.png)
  - [compare/sizes_12px_trio.png](apx-311-text-screenshot/compare/sizes_12px_trio.png)
  - [compare/scaled_6px_trio.png](apx-311-text-screenshot/compare/scaled_6px_trio.png)
- 8 / 12 / 6 px stay readable. No dropped hairlines on `e`, `s`, `a`,
  `8`, or punctuation (`!@#$%…`).
- 8 px is more stair-stepped and higher-contrast than hinted FreeType.
  That is the `screen_px_range` floor of 1.0 making small coverage more
  binary, **not** the D1 halo (which added ink and dimmed interiors).
  APX-269 already called 8 px “slightly heavier than hinted FreeType —
  acceptable.” After APX-270 it is thinner/crisper rather than glow-heavy.
- 12 px is in the FreeType family (crisp, counters open).
- 6 px logical is readable on all three; now higher contrast than the
  pre-fix frame.

If product UI later requires hinted 8 px counters, that is a **new**
work item (hinting or per-size atlas), not leftover D1/D2.

## Shader median / smoothstep / derivatives

The CPU coverage path (what lavapipe actually paints) still implements
`median` + `screen_px_range` with a 1.0 floor + `smoothstep(-0.5, 0.5,
spr * (med - 0.5))`, matching `ui_ps_hlsl`. After the bake contract was
fixed, that formulation produces ~1 px AA at 48–96 px and does not
vanish 8 px text. No new derivative / fwidth defect showed up on this
matrix. GPU sampling was not re-graded (still tofu on lavapipe).

## Conclusion

Every sample that APX-269 marked as a regression now **passes** against
the FreeType reference. The remaining visual deltas (1 px AA instead of
stair-step, ~3 px extra advance / 16 glyphs, unhinted tilde, chunkier
8 px) are the **same residual notes** APX-269 already accepted. They are
**not** the D1/D2/D3 range-mismatch family and **not** a new distinct
root cause.

**Do not replan** atlas resolution, per-size atlases, or the
antialiasing formulation to close APX-269. APX-270’s symmetric
`px_range` `{−1, +1}` + 1:1 unorm approach worked.

Out of scope / still true, not a new screenshot fail:

1. GPU MSDF sampling on lavapipe is still tofu (`SK_UI_MSDF_GPU` off).
2. Harness 48/96 px row overlap is a scene-layout bug, both renderers.
3. No weight variants exist in the matrix.
4. Matching FreeType 8 px hinting would be a new, distinct task.
